## COBOL modernisation pipeline

This release ships a full AI-driven COBOL modernisation capability set. Five new engine executors work together as a sequential pipeline — or independently via the SDK:

| Executor | Produces | What it does |
|---|---|---|
| `RequirementsElicitationExecutor` | `elicitation_report` | Reads workspace docs; identifies ambiguities, contradictions, missing info |
| `COBOLAnalyzerExecutor` | `cobol_analysis` | Parses COBOL source, builds dependency graph, identifies modernisation risks |
| `COBOLGeneratorExecutor` | `cobol_source` | Generates ANS-85-compliant COBOL; enforces structured PERFORM, no GOTO |
| `COBOLRefactorerExecutor` | `cobol_source` (updated) | Refactors source for readability and naming conventions |
| `COBOLSyntaxValidatorExecutor` | `cobol_validation` | Validates via GnuCOBOL or static structural checks |
| `COBOLTestGeneratorExecutor` | `cobol_tests` + `cobol_jcl` | Generates test case specs and JCL skeleton |

```bash
pip install "antcrew[docs,legacy]"   # includes new capabilities
```

### Pipeline template

The platform ships a `template:cobol_modernisation` template with 7 nodes including a HITL review loop. Create it from **Templates → COBOL Modernisation** in the pipeline builder.

### HITL review — new artifact views

The review screen gains three new artifact renderers:
- **`cobol_source`** — line-numbered table with DIVISION headers and copy button
- **`cobol_validation`** — valid/invalid badge with error and warning lists
- **`cobol_tests`** — categorised cards (normal / boundary / error)

## DocumentationReader

New `DocumentationReader` class in `antcrew_engine.documentation` gives engine capabilities a typed API over the doc index: `list_docs()`, `read()`, `search()`, and `*_as_text()` variants formatted for LLM prompts.

```python
from antcrew_engine.documentation import DocumentationManager, DocumentationReader

reader = DocumentationReader(mgr)
cobol_files = reader.list_docs(doc_type="cobol")
source = reader.read("cobol/PAYROLL.cbl")
```

See [Documentation Module → DocumentationReader](../engine/documentation-module.md#documentationreader--structured-access-for-capabilities).

## Document traceability in audit trail

Run attestations now include a `doc_traceability` block recording a SHA-256 snapshot of every indexed document at run-start time. This proves which version of each source file was visible to the AI when it made decisions.

The Compliance Pack ZIP export gains a `doc_traceability.json` file consolidating snapshots across all included runs, keyed by `run_id`.

See [Run attestation → Document traceability](../platform/attestation.md#document-traceability).

## Local documentation storage

The platform now supports local file storage for workspace documentation via the `DOCS_LOCAL_PATH` environment variable. Previously, a workspace without S3 configured would return 422 on doc uploads. The settings UI now shows the upload section and re-index button unconditionally (they were previously gated on S3 being connected).
