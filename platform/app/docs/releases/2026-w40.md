## What's new this week

### antcrew v0.37.0 — Change-management pipeline (T1-T9)

This release adds an end-to-end change-management pipeline for regulated environments: link every AI run to a change-request, analyse COBOL impact, assemble a change package, and route it for approval with a tamper-evident audit trail.

```bash
pip install --upgrade antcrew
pip install "antcrew[release]"   # adds openpyxl for Excel export
```

#### T1 — `change_ref` traceability

Every run can now be tagged with a change-request number. The tag flows from CLI flag → env var → YAML → TraceLog → platform.

```bash
# Flag
antcrew run "Implement order validation" --change-ref CR-4201

# Env var (useful in CI)
ANTCREW_CHANGE_REF=CR-4201 antcrew run "..."

# YAML (agentteam.yaml)
change_ref: CR-4201
```

Filter trace listings by CR:

```bash
antcrew trace --change-ref CR-4201
```

#### T2 — Pluggable VCS adapters (SVN + Git)

`antcrew.adapters.vcs` provides a `VCSAdapter` protocol neutral over any version-control system, with implementations for SVN and Git.

```python
from antcrew.adapters.vcs import get_vcs_adapter

# agentteam.yaml → vcs: {type: svn, url: svn://...}
adapter = get_vcs_adapter(cfg["vcs"])
changesets = adapter.changes_for_ref("CR-4201")
diffs = adapter.diff(changesets[0].changeset_id)
```

Both adapters return `ChangeSet` and `FileDiff` dataclasses — no SVN/Git terminology leaks into application code.

Configure in YAML:

```yaml
vcs:
  type: svn          # or git
  url: svn://svn.company.com/repos/main
  cr_pattern: "CR-\\d+"
  # SVN_USERNAME / SVN_PASSWORD env vars for auth
```

#### T3 — Pluggable issue-tracker adapters (Jira)

`antcrew.adapters.tracker` provides an `IssueTrackerAdapter` protocol with a Jira REST API v3 implementation.

```python
from antcrew.adapters.tracker import get_tracker_adapter, IssueFilter

adapter = get_tracker_adapter(cfg["tracker"])
issues = adapter.fetch_issues(IssueFilter(state="uat", project="ORD"))
```

`IssueFilter.state` maps through a configurable `state_map` — Jira workflow states vary per enterprise:

```yaml
tracker:
  type: jira
  base_url: https://company.atlassian.net
  # JIRA_USER / JIRA_TOKEN env vars for auth
  state_map:
    open: ["Open", "To Do", "In Progress"]
    uat:  ["UAT", "User Acceptance Testing"]
    done: ["Done", "Closed", "Resolved"]
```

#### T4 — COBOL inverse index

`COBOLIndex` builds a SQLite-backed call graph from a COBOL source tree. Query who calls a program, who includes a copybook, and which DB2 tables a program touches — without touching the database.

```python
from antcrew.augment.cobol.index import COBOLIndex

idx = COBOLIndex()
idx.build_from_directory("src/cobol")

print(idx.who_calls("ACCTUPD"))      # → ["MAINPGM", "BATCHJOB"]
print(idx.who_includes("ACCTREC"))   # → ["ACCTUPD", "ACCTINQ"]
print(idx.db2_tables("ACCTUPD"))     # → [{"table": "ACCOUNT", "op": "UPDATE"}, ...]
print(idx.stats())
```

The index is incremental: pass a list of changed file paths after a VCS event to update only those entries.

```python
idx.update_from_files(["src/cobol/ACCTUPD.cbl"])
```

#### T5 — COBOL impact analyzer

`ImpactAnalyzer` consumes the `COBOLIndex` and produces a risk-classified `ImpactAnalysis` for a set of changed files.

```python
from antcrew.augment.impact.analyzer import ImpactAnalyzer

analyzer = ImpactAnalyzer(cobol_index)
result = analyzer.analyze(
    changed_files=["ACCTUPD.cbl", "ACCTREC.cpy"],
    change_ref="CR-4201",
)
print(result.risk_level)    # "high" / "medium" / "low"
print(result.risk_reason)
print(result.as_markdown())
```

Risk heuristics:

| Risk | Condition |
|---|---|
| `high` | DB2 writes (INSERT/UPDATE/DELETE) or >5 downstream callers |
| `medium` | DB2 reads (SELECT) or 2-5 downstream callers |
| `low` | No DB2 access and ≤1 downstream caller |

#### T6 — Release model + CLI

Group change-requests into a release and move it through an approval state machine.

```bash
# Create from explicit refs
antcrew release create Sprint-42 --ref CR-4201 --ref CR-4202

# Create by pulling from Jira (all issues in UAT state)
antcrew release create Sprint-42 --from-jira-state uat

# List and inspect
antcrew release list
antcrew release show REL-A1B2C3D4

# Approve
antcrew release approve REL-A1B2C3D4 --decision approved \
  --approver-id qa@company.com --role qa_lead

# Build change package
antcrew release package REL-A1B2C3D4 --output-dir ./packages \
  --approvers approvers.yaml
```

State machine: `draft → pending_approval → approved / rejected → deployed`

#### T7 — Change packager

`antcrew release package` builds three artefacts from a release:

| Artefact | Contents |
|---|---|
| `{id}_changes.xlsx` | One row per CR with risk-colored rows; configurable columns for ServiceNow import |
| `{id}_summary.md` | Markdown summary with per-CR tables and impact detail |
| `{id}_email_drafts.json` | One email draft per required approver |

Excel output requires `pip install "antcrew[release]"`. The Markdown summary and email drafts are produced without it.

Customize Excel columns for your ServiceNow template in `approvers.yaml`:

```yaml
excel_columns:
  - change_ref
  - summary
  - risk_level
  - modified_components
  - db2_tables
  - test_runs
  - approvers
  - target_date
```

#### T8 — Approvers config

Configure who must approve based on impact risk. One YAML file covers the entire team.

```yaml
# approvers.yaml
approvers:
  - role: qa_lead
    name: "María García"
    email: mgarcia@company.com
    required_if:
      risk: [medium, high]

  - role: risk_officer
    name: "John Smith"
    email: jsmith@company.com
    required: always

  - role: business_owner
    name: "Ana Pérez"
    email: aperez@company.com
    required_if:
      risk: [high]
```

#### T9 — Release approvals in the tamper-evident chain

When recording a release approval, pass `--trace path/to/trace.db` to write the decision into the same SHA-256 hash chain as HITL decisions:

```bash
antcrew release approve REL-A1B2C3D4 \
  --decision approved \
  --approver-id qa@company.com \
  --trace ~/.antcrew/trace.db
```

Each row carries a `row_hash` chaining it to the previous entry. The chain can be verified with `antcrew trace --verify-chain`.
