# Week of 6 Oct 2026

## GitHub SSO (Team+)

Login via GitHub OAuth2 is now available. Users click **Continue with GitHub** on the login page and are provisioned a workspace automatically on first sign-in. Existing accounts with a matching email are linked.

**To enable:**
1. Create a GitHub OAuth App at `github.com/settings/developers`
2. Set `GITHUB_OAUTH_CLIENT_ID` and `GITHUB_OAUTH_CLIENT_SECRET`
3. Set callback URL to `{PLATFORM_BASE_URL}/auth/sso/github/callback`
4. Ensure your license includes the `sso_github` feature (Team tier)

The Runs dashboard now shows a fifth stat card: **Cuota mensual**. The progress bar turns amber at 80% and red at 100%, with an **Upgrade ↗** CTA linked to the pricing page. Free-tier users always see it; paid users see it only when a `run_limit` is set in their license.

## Regulated-tier features

Four Regulated-tier features now have active API endpoints gated behind their license feature flags:

### Retention policy (`retention_policy`)

`GET/PUT /workspaces/{id}/retention-policy` — configure the per-workspace data retention period. When set, terminal runs older than `data_retention_days` are automatically purged by the background loop. Minimum value is 7 days; set to `null` to disable.

### Field encryption status (`field_encryption`)

`GET /workspaces/{id}/encryption-status` — returns whether AES-256-GCM field encryption is active on this platform instance (controlled by `ANTCREW_ENCRYPTION_KEY`), the key length, and the sentinel prefix used on encrypted values.

### DPA template generator (`dpa_templates`)

`GET /workspaces/{id}/dpa-template` — generates a GDPR Art. 28 Data Processing Agreement pre-filled with workspace billing data (entity name, NIF, address). Returns a printable HTML document ready to sign with your DPO.

### Hash chain export (`hash_chain_export`)

`GET /compliance/hash-chain` — fetches the keybridge SHA-256 hash chain audit log and verifies chain integrity. Each entry in the log references the SHA-256 of the previous entry, forming a tamper-evident provenance record of every LLM call made through the proxy.

## ServiceNow integration (`servicenow`)

`GET/PUT /servicenow/config`, `POST /servicenow/test-connection`, `POST /servicenow/runs/{run_id}/incident` — configure ServiceNow credentials per workspace and open incidents or change requests directly from antcrew runs. Credentials are Fernet-encrypted at rest (`SERVICENOW_ENCRYPTION_KEY`).

## SAML SSO stub (`sso_saml`)

The `sso_saml` license feature is now gated at the API layer. Routes `GET /auth/sso/saml`, `POST /auth/sso/saml/callback`, and `GET /auth/sso/saml/metadata` return `501` with setup instructions until `python3-saml` is installed and `SAML_SP_ENTITY_ID` / `SAML_IDP_METADATA_URL` / `SAML_SP_PRIVATE_KEY_PEM` are configured. Contact support for implementation assistance.
